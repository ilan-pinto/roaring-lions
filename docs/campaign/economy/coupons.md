# Coupons

A coupon is a redeemable code that grants brigade credits, Roar TEST coins, or both. The "Redeem code" field on the brigade screen (`/brigade`) takes one.

- **Hashed.** `data/coupons.json` holds `{ id, sha256, credits?, coins? }` per entry (at least one grant), validated by `data/schemas/coupons.schema.json` in `pnpm validate:data` (which also refuses duplicate ids, and two entries under one hash that grant the same kind). The literal code is never in the repository. The code is trimmed and matched case-sensitively against the SHA-256 of its UTF-8 bytes.
- **One code, several entries.** Entries may share a hash. Redeeming a code grants EVERY entry under it that this account has not redeemed, each once on its own id, so a grant added later (the 100,000 coins, entry `lead_roar_coins_100k`, added on 25 Oct beside `lead_special_units_10k`) reaches someone who used the code before: they get the new entry only. A code whose entries are all redeemed refuses as "used". Add a grant to an existing code as a NEW entry under the same hash; never edit a shipped entry's amounts.
- **Coins go to the Roar TEST wallet.** `coupon-redeem.ts` writes the credits to the brigade account and the coins to the wallet (`lions.roar.test`, the one "Grant test coins" fills, a `coupon` receipt on its shelf), and undoes the account write if the wallet write fails. Credits never become coins. A wallet a coupon has filled opens the Stores' TEST mode without `?testcoins` (no Grant button without it), and coin-bought units are single-player only. "Reset brigade account" clears redemptions but not the wallet, so a reset then a redeem grants the coins again.
- **Once per account.** `redeemCoupon` (`packages/app/src/brigade-account.ts`) is pure. A valid code adds its credits to `balance`, appends a `source: 'granted'` grant carrying `couponId`, and records the id in the account's `coupons` list. A second redemption refuses as "used". `earned_total` does not move: it counts credits earned by play. The account version stays 2: a save with no `coupons` field migrates to an empty list.
- **Reset clears redemptions.** "Reset brigade account" removes the whole key, so the code can be used again afterwards. `?fresh` and a new campaign leave the account alone, so redemptions survive both.
- **Trust-based.** The grant is client-side. Anyone can already edit `localStorage` to give themselves credits, so a coupon adds no new exposure, and a hash of a short code can be brute-forced offline: treat a coupon as a convenience for testers, not a secret. The server ledger (GH-205) is where a real entitlement belongs.
- **No sim state.** Balances only: no sim state, no pins, no telemetry event (an attempt would carry the code).
- **Save slots.** A slot snapshots the account with its redemptions, so loading a slot saved before redeeming makes the code usable again. Accepted for the same reason. The wallet is not in a slot, so such a reload grants the coins again (the wallet cap, 1,000,000, still holds).
