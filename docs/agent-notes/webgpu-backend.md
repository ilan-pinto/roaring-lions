# The node (WebGPURenderer) backend: P0 foundations (GH-943)

Design: `_coord/webgpu-primary/design.md` (lead-approved 5 Nov 2026). P0 only: LEGACY STAYS THE DEFAULT and a player sees no change.

- `RendererOptions.gpu` (`auto | webgpu | webgl2 | legacy`, `packages/render/src/gpu.ts`), read from `&gpu=` in the sandbox only (`packages/app/src/gpu-flag.ts`). Absent = legacy.
- `ThreeRenderer` builds a `THREE.WebGLRenderer` ONLY for legacy (`makeGlRenderer`). A node boot never constructs one: two renderers over one scene graph share `light.shadow.map`. `this.renderer` is a getter that throws if a legacy-only path runs on a node boot; every such path is guarded (`photographGround` returns null, `captureView` returns null, the sky environment is not attached) and P1 ports them.
- The node backend is `three/backend/node-backend.ts`, behind its OWN dynamic import. `forceWebGL` is set explicitly and `isWebGPUBackend` is asserted after init. `backendInfo()` says what draws; the one log line is `[lions] renderer: webgpu (<adapter>)` or `renderer: webgl2 fallback: <reason>`.
- P0 draws the scene pass and the output transform only. `three/backend/unported.ts` censuses every `onBeforeCompile` / `ShaderMaterial` / render-target envMap (`renderer.unportedHooks()`); `ShaderMaterial` objects are HIDDEN on the node path.
- Visual gate: `--gpu=legacy|webgl2|webgpu` on `golden-baseline`. The envKey backend term (`-wgl2`, `-wgpu`) comes from `backendInfo()` read on the page; legacy keys are unchanged (pinned against every committed baseline directory). Node arms freeze the loop with `window.__lionsFreezeLoop` (`packages/app/src/frame-freeze.ts`), never a stubbed rAF, and photograph only after two zero-time repaints read byte-identical. Mixed-backend runs are refused (exit 2). Nothing is blessed for a node key before P7.
- `tools/webgpu_ratchet.mjs`: the ESLint ratchet. `PORTED_FILES` starts empty and only gains entries.
- TODO(P7): the four synchronous `webgl2Available` screens switch to `ui/gpu-probe.ts`'s `drawableNow()`; the settings panel and the feedback note show `backendInfo()`.
- P2 T1 (the material seam, GH-943): `RenderBackend.materials` is a `MaterialKit` (`ground`, `foliage`, `ring`), each `null` until T3/T6/T5 land it. `ThreeRenderer.adoptNodeMaterials` swaps `mesh.material` legacy -> twin through an identity cache (`node-material-adoption.ts`, keyed on the legacy program key or the ring's name `rl-selection-ring`); it runs in `init`'s node branch before `prepare`'s first census, and in `rebuildTerrain` after the ground update and the decor build (full build, collapse splice and chunk re-slice alike). The legacy object keeps the uniforms and debug setters; `SelectionRingBatch.material` is held apart from `mesh.material` for that. A twin lists what it does not draw in `userData.rlUnportedTerms` (the census's `partial` kind). `PORTED_MATERIAL_KEYS` (`backend/unported.ts`) gains a key in the PR that lands its twin, and is read only through `censusUnported(root, { portedKeys })`, which only `matchNodeStatements` passes (`match-node-ported-keys.test.ts`). Twin maths arrives as values (`material-maths.ts`, `NodeBackendOptions.materialMaths`), never a value import (the bundle census's `MATERIAL_MATHS_MARKER`); a twin's material `name` starts `rl-node-material-` so the census can place it. `Ops<T>` carries min/max/abs/floor/step/pow/cos/atan2/sqrt/exp/sign and `IntOps<T>` the uint hash (`tileHashOps` in `tile-hash.ts`): no `tan`, `atan`, `mod` or derivative, by design.
- P2 T3 (the node ground, GH-943): `terrain/mesh.node.ts` is the `materials.ground` twin, a `MeshStandardNodeMaterial` (`rl-node-material-ground`, `vertexColors` false because the graph reads `vertexColor()` itself) whose `colorNode` is the DRY blend: five unconditional slot taps, controls A/B, height bias and rescale, the road (BRANCH-FREE, its knoll grain tap a `textureGrad` whose `dFdx`/`dFdy` are emitted as statements at the top of `main`), the tones, then albedo x macro. The maths is written once in `terrain/ground-maths.ts` (a leaf that now owns the road cross-section, `HEIGHT_BLEND` and `MACRO_*` constants; `road-graph.ts` and `control-map.ts` re-export them, and `roadProfile`/`heightBiased`/`macroFactor` run it through `NUMBER_OPS`). The twin re-binds every number, vector and texture from the legacy record each render (a texture rides on its slot's strength uniform, the controls and macro on `uMapSize`, because a texture node's own update type is reset at setup); each tap is `texture(value, uv)`, so it applies no `texture.matrix`, as the legacy GLSL does not. TSL `select` compiles to an `if`/`else` block, so "branch-free" in TSL still has `if`s in the output: `sample-uniformity.ts`'s `assertNoImplicitSampleInConditional` is the guard (no implicit-gradient sample inside any conditional body). Not drawn, and named by the census's `partial` kind: `rl-ground: relief read` (T4) and, on a wet owner, `rl-ground: wet terms` (P4); a wet owner compiles the dry graph byte for byte. `rl-ground` is on `PORTED_MATERIAL_KEYS`; the wet keys are not.
- P2 T4 (the relief read on the node ground, GH-943): `terrain/relief-read.ts` now writes its scalar parts once against `Ops<T>` (`reliefTiltOps`, `contourFactorOps`, `reliefTintRampOps`; the legacy `exaggerateNormal`, `contourFactor`, `reliefTint` run them through `NUMBER_OPS`, signatures unchanged), handed to the twin as values (`MATERIAL_MATHS.ground.relief`). `mesh.node.ts` adds the slope light as the twin's `normalNode` (VIEW space, lighting only: shadows and the real geometry are untouched; world vertex normal x `faceDirection`, tilted, pass-through where `y <= 0` or `h < 1e-6`, back to view with `cameraViewMatrix`) and the contour and tint as a multiplier on tops. The contour rate is `fwidth(levels)` emitted as a STATEMENT at the top of `main` (a derivative in uniform control flow, WGSL-safe; pinned on GLSL and WGSL by `mesh.node.test.ts`). A `normalNode` is built only when the scene has a light, so the relief tests compile LIT (opt-in `compile(owner, true)`; a lit build adds a ninth sampler, the standard material's BRDF lookup, so the sampler-count gates stay unlit). A dry node ground now names nothing as unported. Lesson from T3: a placeholder texture a twin samples must not be Nearest/Nearest (a WGSL program bakes the texture's filterability at its first build). R9: the aftermath node readings after the `decals` toggle were contaminated because the toggle re-shows the census-hidden decal `ShaderMaterial` pools and the frozen frame loop never re-ran the census; `layerToggleScript` now re-runs the node census (`nodeCensusStatements`) on a node arm, but only when the caller passes `scriptOpts.nodeCensusRoot`; `three-baseline-gate.ts` sets it for every non-legacy arm, and a caller that omits it gets no census (the toggle then repeats the contamination).
- P2 T6 (the node foliage, GH-943): `terrain/decor-mesh.node.ts` is the swaying foliage/trunk twin, a `MeshStandardNodeMaterial` whose `positionNode` adds the wind (`foliageLeanOps` in `wind.ts`, the one body the number tests run; mode 0 is the reduced-motion sway, `wet`/`trunk` are JS graph choices). The legacy material carries its record as `rlSway` (`SwayRecord`: the clock, `amp`, the resolved wind and disturber sets, the variants and key), which the twin re-reads every render. Three r186 facts it is built on, each pinned in `decor-mesh.node.test.ts`: `setupPosition` runs `batch()` before `positionNode`, so the twin reads the BATCHED `positionLocal`; the instance origin is the matrices texture's texel `4 * vBatchIndirectId + 3` (three's own fetch, column 3 only); the shadow pass takes `castShadowPositionNode` (the rest position); and a `PassNode` override (the node AO pre-pass) is HANDED the material's `positionNode` (`Renderer.js`, "overrideMaterial.positionNode = material.positionNode"), so the AO pre-pass does NOT keep the rest pose by construction: the twin's position graph returns the rest position for any program that is not its own or a shadow pass's. The disturbers (N2/N3) are the census's `partial` term `rl-foliage-sway: disturb` until T7 adds them as a `FoliageTerm`.
- P2 T7 (the vehicle bend and rotor wash, GH-943): the disturbers are a `FoliageTerm` in the same twin, summed with the wind before the frame change. `disturb.ts` holds the maths once against `Ops<T>` (`disturbSlotPushOps` per slot, `disturbBendOps` after the loop; `disturbDisplacement` and the scalar exports are those bodies on `NUMBER_OPS`, run against literals in `disturb-ops.test.ts` and the transpiled GLSL in `disturb.test.ts`); the twin gets them as values (`FoliageMaths`). The slot arrays are `uniformArray` nodes (Vector4/Vector3 elements) that COPY the record's flat `Float32Array`s in their render update, because `ThreeRenderer` points `disturbU.a.value`/`b.value` at the field after the record exists; one set per record, shared by the four twins. The loop bound is the preset's `DisturbUniformSet.slots` (24/16/8), with the legacy `break` at `uDisturbN` and the count x layer and bounding-box early-outs. The thrash runs only where `wash > 1e-4` (the GLSL's gate; the old TS mirror did not gate a NEGATIVE wash, which the spring can produce, so it now follows the GLSL). Shadow and AO keep the rest pose through the T6 guards. The twin declares no unported term any more. `ThreeRenderer.disturb-twin-clock.test.ts` reads the nodes the twin holds after two frame cadences.
- P2 T5 (the rings, GH-943): `units/selection-ring.node.ts` is the twin of all three ring batches (selection, team, wound arc), a `MeshBasicNodeMaterial` with the legacy blend; the coverage is `ringFragmentOps` (selection-ring.ts, `Ops<T>`, handed over through `MATERIAL_MATHS.ring`). It reads the legacy material's uniform record (`SelectionRingBatch.material`, the batch's own writes) and the `RingStyle` the legacy material carries in `userData.rlRingStyle` (a copy of the key lives in the twin, pinned equal by test). `rl-selection-ring` is on `PORTED_MATERIAL_KEYS`. The `selection-ring` debug layer hides `selectionRingGroup` on both paths. `vehicle/selection-ring` in `baseline.ts` carries INFINITE floors (listed in `PENDING_FLOOR` in `baseline.test.ts`) until its first three CI readings are written: the `visual` job is red on purpose until then.
- P3 T8 (overlays, zone band, supply route, trail, GH-943): four `MeshBasicNodeMaterial` twins (`units/overlays.node.ts`, `units/zone-band.node.ts`, `supply-route.node.ts`, `trail-mesh.node.ts`), each reading its attributes by name. The factories take NO legacy material, only the uniform record they bind (the ratchet bans the `ShaderMaterial` type name in a twin file). The pipeline state (the overlay's `depthTest: false`, the zone band's decal multiply, the route's polygon offset) is the legacy material's, copied by adoption (`copyRenderState`), so a state key dropped from `RENDER_STATE_KEYS` moves the twin. The hatch (`zoneHatchOps`, `zone-band.ts`) and the dash (`dashOps`, `supply-route-maths.ts`) are `Ops<T>` maths handed over by `MATERIAL_MATHS`. The supply route's colours are the legacy `uOpen`/`uCut` vectors bound BY REFERENCE (`setColors` writes them in place). `SupplyRouteMesh.sync` returns true when it makes a mesh and `ThreeRenderer` queues that group for adoption, because the mesh is made after init. A twin compiled in a test needs `copyRenderState` first: without it `transparent` is false and the program forces alpha 1.
- P3 T1 (the unit seam, GH-943): `MaterialKit`/`MaterialMaths` carry 18 P3 slots, all `null` until T3-T12. A P3 `ShaderMaterial` is recognised by its `name` (`material-names.ts`, `P3_MATERIAL_NAMES`; one `name:` line per batch, which moves no program); a hooked material by its `rl-` program-key segments (`hookSegments`): all in `UNIT_HOOK_SEGMENTS` is `unit`, and `rl-silhouette-outline`, `rl-garrison-banner` and `rl-backdrop-fade` (the backdrop's constant key) are `outline`, `banner` and `backdrop`. The census keys a hooked material by `censusKey` (segments joined by `|`) and exempts it only when EVERY segment is on `PORTED_MATERIAL_KEYS`; its `unadopted` kind (`[lions] UNADOPTED`, table injected as `NodeBackendOptions.twinSlotOf`) is the backstop for a swap site that forgets. Every unit swap site calls `ThreeRenderer.queueNodeAdoption(root)` (node-only); `flushNodeAdoption` adopts the queue at the top of every node render and then mirrors each live twin's `visible` from its legacy material (ruling P3-R4). `unit` twins are SHARED and refcounted by (`legacyBaseOf`, segments, transparent, side, stencil): running-gear, fade and scar clones record their base (`recordLegacyBase`) and share it; team variants never do. Every clone site clones `legacyOf(mesh.material, mesh)` (`twin-identity.ts`): the per-mesh record first (ruling P3-R2), the twin's `rlLegacy` second; records are NON-ENUMERABLE so no `clone()`/`toJSON` serialises a material. P3 twins take `copyRenderState` (`RENDER_STATE_KEYS`, 25 keys). `twin-identity.ts` and `material-names.ts` import nothing and live in their own `twin-seam` chunk (`vite.config.ts`): hoisted into ThreeRenderer they made the node backend load the legacy composer. `flipbook-fx.ts` and `smoke-mesh.ts` wrote uniforms through `mesh.material`; T12 holds their legacy materials apart.
- P3 T11 (the simple FX twins, GH-943): `particle`, `tracer`, `vfxMesh`, `rimFade`, `beam` and `rotor` are filled by `units/fx-twins.node.ts` (the ONE wiring, spread into the kit by `node-backend.ts` and rebuilt by the specs via `fx-twin-test-kit.ts`). Each twin is an unlit `MeshBasicNodeMaterial` (`fog = false`, `toneMapped = false`) reading the legacy material's record (numbers re-read per render, `Color`s by reference) and the batch's attributes; it has NO clock (frame-clock families are written into attributes by the batches, beam geometry and rotor phase by the sim clock), pinned by `compileFx(...).frameClocked`. The maths is `Ops<T>` in the legacy files (`softParticleOps`, `rimFadeOps`, `beamShapeOps`, `rotorBlurOps`/`rotorSpinOps`) and the legacy GLSL spells the same constants (`SOFT_PARTICLE_CORE`, `COLLAPSE_SHROUD_SHADE_BREAKS`, `BEAM_DISC_FEATHER_FROM`, `ROTOR_*`), so they cannot drift. The plume and shroud share `rim-fade.node.ts`: |N.V| is read from `normalLocal` AFTER three's instance step (an inverse-transpose, which is the plume's exact non-uniform-scale correction). The beam twin has no discard (the disc factor is already 0 past the rim). Late-built meshes (muzzle, burst, plume loaders, the per-mission swarm batch) call `queueNodeAdoption` themselves, because `init` adopted the scene before they existed. None of these writers goes through `mesh.material` (`fx-twins.node.test.ts` scans for it).
- P3 T12 (the flipbook and the smoke screen, GH-943): `flipbook` and `smokeScreen` join `fx-twins.node.ts`. The shared billow noise (sin-hash, 4-octave fbm, the atlas cell, the sun shade, the billboard) is ONE `Ops<T>` module, `units/vfx-noise.ts`, three-free; each legacy shader keeps its own GLSL copy, pinned to that module's constants by `vfx-noise.test.ts`, which also pins the module to a literal reading of the GLSL. Both vertex stages are clip-space `vertexNode`s; the smoke screen reads its instance matrix through a second instanced view of `instanceMatrix.array` (`OnBeforeObjectUpdate` copies the version), because three's instance step only transforms `positionLocal`. **An atlas tap must be a STATEMENT**: outside a `Fn` a `toVar()` is emitted where it is first read, which for a `select` operand is inside the generated `if` (TSL lowers `select` to an if/else in GLSL), so each fragment is one `Fn` whose taps are `toVar()`'d before anything selects, and the discard is packed into its alpha (-1, `keptOf`) so one call is both `colorNode` and `maskNode`. **One placeholder per atlas key**: three shares a texture binding between taps of the same texture, so two atlases built on one placeholder compile into one sampler. Late atlases re-sync on a carrier uniform's render update (`vfxRecord`). `FlipbookFx` and `SmokeMesh` hold their legacy materials apart (`smokeMaterial`/`fireMaterial`, `material`).

## Banding (P2 T2)

The lead saw banding in the large soft shadow and on the lit ground of the node (G) frames of the P1 v2 sheet. T2 measured it; T8 fixes it.

**Cause.** 8-bit quantisation of smooth gradients, with NO dither on a day map, on BOTH paths. L hides it under the ground texture; G has no ground texture yet (the legacy splice is not ported, T3), so it shows it. Three readings settle it:
- **H0:** the legacy frame with `ground-albedo` and `macro` hidden (the flat palette ground G draws) bands like G: 0.563 / 0.636 (penumbra / lit) on Metal, against G's 0.636 / 0.679 and textured L's 0.001 / 0.000.
- **H1:** the output dither runs only while a grade is on (`uGradeOn > 0.5`, `output-grade.ts`, the node twin alike). `wadi_halam_4` is a day map with no grade, so `uGradeOn` reads 0 on both arms and nothing is dithered. Forcing the dither on (a near-identity grade, `uGradeDither` 1) takes G from 0.636 / 0.679 to 0.064 / 0.054 (Metal). Dither on with `uGradeDither` 0 leaves it banded (0.649 / 0.666).
- **The large soft "shadow" is the fog-of-war shroud, not a shadow map (HX).** Revealing every tile (`fog` hidden) moves 51,334 of the penumbra crop's 67,584 px (mean channel delta 52 over the frame). Every shadow toggle moves at most 470 px of that crop and leaves the index where it was.

**Not the cause.** H2: the node chain is HalfFloat end to end until the canvas (scene pass `rgba16float`, depth `depth24plus-stencil8`, SMAA input `rgba16float`, canvas `bgra8unorm`, `srgb`, tone mapping `standard`); the scene pass at FloatType reads 0.636 / 0.683. H3: `shadow.radius` 0 and 4 (1 ships), BasicShadowMap and VSM do not move the index (node shadow depth `depth24plus`, UnsignedInt `Depth`, the same compare as legacy). H4: AO off RAISES G's index a little (0.693 / 0.697; its noise breaks plateaus). H5: the sky light moves no ground pixel (the ground takes no environment, by design). The node dither's y flip is right: the dither-on minus dither-off difference correlates with the bottom-left IGN at 0.725-0.766 on L and G, and with the top-left one at under 0.01.

**Recommended fix for T8: run the dither always, not only with a grade, on both paths.** One LSB of the same IGN after the output transform (drop the `uGradeOn > 0.5` guard on the dither, keep it on the LUT). On the legacy path that alone is not enough: `OutputGrade.apply(null)` (no grade, or an identity) swaps the shader back to `baseFragment`, and the dither is compiled in only by the folded shader (`foldGradeShader`), so the null-grade path needs the dither in the base shader and `uGradeDither` set on that branch too. It changes legacy: every L frame gains a one-LSB noise (2.7 M px moved at mean 0.26 channel units on this framing, invisible on textured ground), so every golden baseline moves, and per ruling 2 the PR waits for the lead's look and a CI bless. T3's texture port alone would bring G to L on these crops (textured L reads 0.000), but the flat-palette reading shows any untextured gradient (the shroud edge, a dusk sky term, a future flat material) bands on both paths without the dither. Rectangular (1 LSB) is enough on these crops (0.05-0.06); on the shallowest gradient the metric masks (1 level per 32 px) it leaves 11-13 px plateaus at every level crossing (synthetic 0.177), and a triangular dither (two IGN samples, 2 LSB) reads 0.000 there. T8 can choose; the measured default is rectangular.

**Instruments.** `tools/src/golden-diff/banding.ts` (`bandingIndex`: the mask is a 9x9 box-blurred luma changing 0.5-4 levels over 32 px; the index is the masked pixels in a run of 12+ px of identical 8-bit luma, read along the gradient's axis, that ends in a 1-level step; an empty mask is a refusal). Its fixtures, `fixtures/banding/` (the four P1 v2 crops, G 0.636 / 0.679 and L-shipped 0.001 / 0.000), prove it sees the defect. `tools/src/perf/webgpu-banding-probe.ts` reads every hypothesis on every arm and refuses a HYPOTHESIS none of whose variants moved a stable pixel on any arm (`deadHypotheses` sums the changed pixels per hypothesis across its variants and arms, so one dead variant beside a live one is not refused); on CI it runs from `webgpu-noise.yml` (`gh workflow run webgpu-noise.yml --ref <branch> -f probe=banding`).
