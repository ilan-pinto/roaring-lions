**Goal:** the node renderer on WebGPU (G) draws every unit, decal, overlay and effect the legacy renderer (L) draws, with no
hidden object and no dropped hook left in the node census except the named P4 and P6 items, and the 600-unit frame cost no
worse than the ×1.073 the lead accepted through P3 (GH-1152). The 1.05 bar at n600 returns in P6.

**The lead's rulings on this plan (8 Nov, PR 1153, recorded on GH-943).** These are no longer open questions:

   phase (P6, speed, before the P7 cutover).
3. **The `occluded` scenario is approved** if T5 Step A needs it.

**Architecture:** the P2 material seam (`MaterialKit`, `adoptNodeMaterials`, the partial census, `PORTED_MATERIAL_KEYS`) gains
a slot per P3 material family. Each P3 task writes the node twin of one legacy file, beside it, in the same PR. The
`onBeforeCompile` hooks on unit materials compose (running gear then team mark; rain rim then wounded floor). A single `unit`
twin therefore composes the TSL terms that match the hook segments of the legacy material's program key. The unit materials are
swapped mid-mission (spawn, running-gear bind, scar band, death fade, reload), so P3 adds what P2 never needed: adoption at
every unit swap site, and clone sites that resolve a twin back to its legacy material before cloning. GH-1152 runs as a
diagnosis task and a fix task, measured after the unit ports, because the ports add node materials to every unit.

**Tech Stack:** TypeScript strict, three 0.186.1 (pinned), `three/webgpu` and `three/tsl`, vitest, Playwright Chromium (ANGLE
Metal locally, SwiftShader on CI), GitHub Actions (`visual`, `visual-backends`, `visual-parity`, `webgpu-noise.yml`).

## Parity method

- **The ratio** is P1's: r = Δnode / Δlegacy-matched, where Δ is the shown-minus-hidden meanAbsChannelDelta (primary) and the
  changed pixels (secondary).
- **DEAD.** A node delta under its node floor reads DEAD: a third of the smallest of 3 CI runs per key. It is report-only, so a
  DEAD falsification is a PRINTED WITNESS: the task copies the run id, row and delta into its commit message and PR. The vitest
  gates are the ones that go red.
- **Gated rows** go in `golden-diff/parity-bands.ts`, read by `visual-parity`. A row's `layer` must be a `layerChecks` name.
- **Ungated rows** (no gated scenario shows the thing) go in the units/fx probe (T2), on CI SwiftShader through
  `webgpu-noise.yml`. They take the same ratio, bands and DEAD verdict, and the probe prints them as a table and a job summary.
- **Bands** (unchanged classes):
  - `tight` [0.95, 1.05]: analytic, untextured;
  - `loose` [0.85, 1.15]: textured or filtered;
  - `ao` [0.70, 1.30]: small Metal-measured floors, or lighting- and shadow-dependent;
  - `zero`.
- **L-matched must draw what node now draws.** Each port appends its key to `PORTED_MATERIAL_KEYS`, read per hook SEGMENT (T1),
  so a ported legacy material stays visible on L-matched.
- **R14.** Every r0 recorded before the L-matched settle fix (PR 1134) is on main is re-read after it, at T15.

## The standard task loop

Every task runs these steps, in this order, in its own worktree from origin/main. A stacked task branches from its parent's
head and merges main in. The task text below adds its own steps between 2 and 3.

- [ ] 1. Read the task's legacy file(s), its §0 facts, and the twin it stacks on (if any) by sha. Write each gate below as a
      failing vitest first, and run it to watch it fail for the stated reason.
- [ ] 2. Implement the twin, the maths and the wiring until the gates pass:
      `pnpm --filter @lions/render test -- <spec files>`, then `pnpm lint`, `pnpm typecheck` and
      `pnpm --filter @lions/tools webgpu:bundle`.
- [ ] 3. Falsify every new gate with the one-line mutation it names. Watch it go red, undo the edit by hand (never
      `git checkout <file>`), and list each mutation and its red test in the commit message.
- [ ] 4. Commit with `git commit -- <paths>`. Push and open the PR (refs GH-943, plus GH-1152 for T13 and T14), with the S, G and
      P lines and "Decisions".
- [ ] 5. CI: read `visual` (legacy must be green with no bless, unless the task says otherwise), `visual-backends` (0 validation
      errors, no black or flat frame) and `visual-parity`. For probe rows, run
      `gh workflow run webgpu-noise.yml --ref <branch> -f probe=<units|fx>` three times. Record r0 and the node floors into the
      task's rows from those runs, then push the DEAD witness mutation once, copy the printed line, and revert.
- [ ] 6. Mirror the ledger to `_coord/webgpu-p3-progress.md`.

## Risks

1. **The unit adoption is the new failure surface.** P2 adopted at three sites. P3 must adopt at about twelve and at every clone
   site, and a missed one draws the STOCK material for up to 60 frames on node: an unmarked tank, or a figure with no rim, with
   no error. T1's G1/G2 walk and the `UNADOPTED` census kind are the guards. A reviewer should read every `mesh.material =` in
   `ThreeRenderer.ts` and `units/` against the queue.
2. **A program per vehicle.** A twin per running-gear clone or fade clone would compile a node program mid-battle: a stall on
   the first move or the first death. T1's shared memo and T3's object-scoped uniforms avoid it, and T1 G3 pins it. If three
   r186 keys a program on uniform-node identity anyway, the fallback is one twin per template with every per-entity value
   object-scoped. Measure before choosing.
3. **Skinned outline maths.** r186 skins before `positionNode`. Getting the bone matrices into the twin depends on SkinningNode
   internals, and the pin breaks loudly at a three upgrade (the P2 BatchNode precedent). T5 G1 holds the maths. The fallback is
   a pre-skinned expansion attribute, which costs memory: report before taking it.
4. **The crater rim's light access.** Reading the scene's light objects and the sun's shadow from a non-lit node material is
   the deepest node API use in P3. If it does not hold, the fallback is a lit node material whose lighting result is divided
   out, at more cost: report before taking it.
5. **WGSL uniformity in the flipbook.** The legacy samples inside a varying branch after a discard. T12 rewrites it branch-free.
   The content gate on wgpu catches a miss, but only on the probe frames, because no gated scenario has a flipbook.
6. **P3 raises G's CPU cost before T14 lowers it.** Every ported unit becomes a node-material object with a FULL refresh. The
   n600 ratio can get worse at T3 and T5, past the ×1.073 the lead accepted through P3. T13 reads before and after (H6), and
   the bar is judged only at T14.
7. **Census-key churn.** T1 renames the census keys (segments, names). Every tool that reads the census (`webgpu-p2-sheet-lib.ts`'s
   `CENSUS_RULES`, `unported.test.ts`) moves with it, in T1, so a stale classifier cannot mark an entry "expected" by an old name.
8. **The ungated witness is report-only.** Running gear, rim, floor, soot, banner, overlays, x-ray, backdrop and every VFX have
   no gated scenario, so a regression on node shows as a DEAD or out-of-band probe row, not a red PR. The vitest wiring gates
   (R12) are the reds. The sheet is where the lead judges the look.
9. **Same-PR friction.** `fx.ts`, `decal-maths.ts`, `silhouette.ts` and `team-mask.ts` gain twins, so an unrelated look change
   there must touch the twin. That is the rule doing its job.
10. **CI queue time.** P2's runners queued for hours. Each port task needs 3 probe dispatches plus its visual floor runs. The
    controller should batch the dispatches, and never fall back to a local golden-baseline.
