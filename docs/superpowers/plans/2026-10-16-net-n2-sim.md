# N2 · The Sim Learns Seats: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The sim is seat-aware and the mission runtime is network-hashable.
1. A `humanHeld` seat table, passed in at construction, decides who never
   auto-breaches. Single-player keeps today's rule, and a versus room exempts
   both seats.
2. `setStance` (`hold`, `ambush`), `build` and `support` become tick-stamped
   `Command`s, and the wire whitelist changes in the same commit.
3. `MissionRuntime.digest()` is born and pinned, and wired through the
   existing `FrameStep.runtimeDigest` seam.

**Architecture:** Option B, ruled as L1 (15 Oct, coordinator, lead-delegated).
- The `Sim` takes `SimConfig.humanHeld` from `seatRules` in `@lions/net` and
  never reads a config. `selectBreachTarget` asks the table instead of
  testing `side === 0`.
- A versus room still runs **no** `MissionRuntime` until N3. So `build` and
  `support` are priced only where a runtime exists (single-player and
  missions). In a versus room they are dropped by `validateCommand` on both
  machines, the way `callStrike` and `reveal` already are (#559).
- The sim never executes `build` or `support`. `queueCommand` sets them aside,
  the runtime drains them **before** `sim.tick()` (`applyQueued`), and a tick
  that starts with them still set aside discards them.
- With the drain before the tick, a build's start tick and a support call's
  rounds land exactly where a direct call between ticks puts them today.

**Tech Stack:** TypeScript strict, vitest, `@lions/sim`, `@lions/net`,
`packages/app`, and `tools/` (backtests and the net harness). No new
dependency.

## Global Constraints

- **The four invariants** (CLAUDE.md):
  - fixed 20 Hz tick;
  - Q16.16 with no floating point in `@lions/sim`, so every new field is an
    int or an `Fx` and the ambush radius is a Q16.16 integer;
  - seeded per-entity RNG, with no new draw anywhere;
  - commands in, sim, then state and events out. `build` and `support` are
    data the app queues. The runtime reads them from the sim's set-aside list.
    Nothing outside the sim writes sim state. One acknowledged edge:
    `Sim.takeRuntimeCommands()` lets the runtime drain a sim-owned, unhashed
    queue from outside the tick. That is queue plumbing on the input side,
    not a state write: the sim never executes those two kinds, and nothing it
    hashes changes when the list is drained.
- **Option B (L1): no versus `MissionRuntime` in N2.**
  - `main.ts` keeps `runtime === null` in a room.
  - `SeatWorld.versus`'s drop of `callStrike` and `reveal` stays, and
    `build` and `support` join it.
- **The sim never reads a config.** `humanHeld` arrives as a constructor
  argument. `seatRules(config)` (`packages/net/src/seat-rules.ts`) is the only
  thing that derives it:
  - versus gives `[true, true]`;
  - single-player and a sandbox room give `[true, false]`.
- **No pin moves except the ones this plan says are born.** The pin table at
  the end predicts every pin per task. A pin that moves without a row saying
  it may is a defect to explain before the task continues, not a re-pin.
- **`COMMAND_KINDS`, `cleanCommand` and `validateCommand` change in the same
  commit as the `Command` union.** P1's `MissingCommandKind` makes a
  forgotten kind a compile error. `cleanCommand`'s `never` default and
  `validateCommand`'s exhaustive switch do the same.
- **`pnpm test:determinism` passes before every commit touching
  `packages/sim`.** So do `pnpm typecheck` (CI runs it; CLAUDE.md omits it)
  and `pnpm lint`.
- **Every check arrives with its falsification, watched red** (CLAUDE.md). The
  cheapest falsification is a one-line mutation of the implementation. Each
  commit message lists its mutations and what went red. A survivor is
  disclosed, not papered over.
- **`pnpm playtest` and `pnpm balance` stay byte-identical** to the baselines
  the pre-flight records, apart from timing lines. Neither reaches any line
  N2 changes with a non-default value.
- Git:
  - `/usr/bin/git` by absolute path, one plain command per call;
  - commit with `/usr/bin/git commit -s -F <msgfile> -- <paths>`;
  - never `git add -A`, `git stash`, `git checkout -- <file>`, a rebase or a
    force-push;
  - messages end with a blank line and
    `Co-Authored-By: Claude <model name> <noreply@anthropic.com>`.
- **Never start or kill a dev server, and never `pkill`.** `pnpm ui:routes`
  and `pnpm golden-baseline` run on CI only. Test browsers start with music
  off.
- UI strings go through `t()` in `packages/app/src/i18n/en.json`, and
  `pnpm validate:ui` stays green.
- Tasks are signed off one by one. The PR merges without squashing.

**Rulings this plan makes itself, each cheap to reverse (they stand: 16 Oct, lead):**

- **R-1. The ambush radius.** It is `AMBUSH_RADIUS_DEFAULT = 196608` (3 tiles,
  mission JSON's own default) and `AMBUSH_RADIUS_MAX = 655360` (10 tiles, the
  largest `tiles` any shipped mission authors), both in `tuning.ts`. The wire
  refuses `radius <= 0`, a radius over the maximum and a non-integer.
- **R-2. `humanHeld` is not hashed.** It is a construction-time constant both
  clients derive from the shared config, exactly like `seed`. Hashing it would
  move all three sim pins and every versus pin with no behaviour change,
  against option B's "the pins do not move". A client built with the wrong
  table diverges in state the first time the rule acts, and the state hash
  sees that.
- **R-3. Runtime commands do not survive a tick.** `build` and `support`
  still set aside when `applyCommands` starts are discarded: no runtime took
  them (a sandbox room, a versus room before validation, `__lions` in a
  sandbox). They never run late and never accumulate.
- **R-4. `SupportKind` and `FIRE_SUPPORT_KINDS` move from `mission.ts` to
  `tuning.ts`**, beside `FS_*`, so `sim.ts` can name them without importing
  `mission.ts`. `mission.ts` re-exports both, so every import site and
  `index.ts` stay as they are.
- **R-5. What `digest()` folds:** only state with a twin test that isolates
  it (Task 6). The excluded runtime state is listed with its reason, so a
  later reader knows it was a choice.

## Review Focus

1. **A tampered or confused client sends a `build` or `support` for the other
   side, in a versus room, or with a bad unit id or support kind.** Expected:
   `cleanCommand` refuses the shape and `validateCommand` drops the rest (the
   side is not the seat's side, or the room is versus), identically on both
   machines. The room stamps only cleaned commands. Pinned in Task 4.
2. **A `setStance{ambush}` naming a garrisoned, carried, buried, routed or
   dead unit, or a radius of 0, −1, 2^31, 3.5 tiles as a float, or 11 tiles.**
   Expected: the wire refuses a bad radius. The sim skips each unsuitable id
   as a no-op, while the rest of the command still applies to the others.
   Pinned in Task 3.
3. **Two purchases in one frame where the purse covers one.** Expected: the
   first is queued, and the second is refused at `applyQueued` and spends
   nothing. Neither runs late. The UI's pre-check said yes to both (D3), and
   the plan says so instead of hiding it. Pinned in Tasks 4 and 5.
4. **A `build` or `support` queued in a world with no runtime** (a sandbox
   room, or `__lions.sim.queueCommand` in Free Play). Expected: it is
   discarded at the next tick (R-3). The set-aside list is empty after every
   tick, and no hash moves. Pinned in Task 4.
5. **`setStance{hold}` on a unit inside a building, or on one with a live
   `attack` focus.** Expected: the garrisoned unit stays inside and its stance
   is unchanged. The focused unit loses its focus, as every order but
   `attack` takes it, and halts. Pinned in Task 3.
