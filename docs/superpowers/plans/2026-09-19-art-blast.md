# The blast — vehicle death and mortar impact (WP-A1.2, GH-172) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vehicle dying and a mortar bomb landing read as detonations with weight. One sequence — flash, on-palette hot fireball, a twenty-second smoke column, a scorch mark that stays, the wreck swap hidden under the collapse shroud — dispatched from the two places a blast can originate, sharing every piece, with the mortar and the Grad taking their own share of it at `impactPower`. The screen shakes and the picture stops for a beat, from numbers `data/vfx/catastrophic_kill.json` has declared since the schema was written and nothing has ever read.

**Architecture:** Four of the five sequence elements already ship and are not re-implemented (`docs/superpowers/specs/2026-09-19-art-blast-design.md`, "What exists today"). What is new is small and almost all of it is pure: `three/scorch-decals.ts` (a `vehicle-tracks.ts`-shaped ring buffer), `three/blast-shake.ts` (two pure models — a shake amplitude curve and a hit-stop clamp), `three/blast-spec.ts` (what an emitter's `light`/`screen_shake`/`hit_stop_ms` mean once scaled by a power term), an absolute rise/fade window on `units/smoke-plume.ts`, and a `vehicleShroudBounds` on `units/mesh-vehicle.ts`. `ThreeRenderer.ts` is touched exactly once, in one task, in three adjacent regions (Ruling R-F). `packages/sim` is untouched; `packages/app` is untouched; `packages/render/src/renderer.ts` stays byte-identical to `main`.

**Tech Stack:** TypeScript strict, vitest (`environment: 'node'` for every file here), three.js r1xx, Playwright (the capture harness only). No new dependencies. No schema change — `vfx_emitter.schema.json` already declares every field this package reads.

**Spec:** `docs/superpowers/specs/2026-09-19-art-blast-design.md` — Decisions R-A…R-S, Constraints, Architecture, Testing and evidence. The spec is the binding authority; this plan argues from it. Execution-plan package **WP-A1.2 (#172)**, art lane Phase 1 · Weight, sub-project 2. One branch (`feat/art-blast`), one landing, one bless budgeted and none expected (R-L).

## Global Constraints

Copied from the spec's "Constraints that bind every task", binding on every task below:

- **The four invariants.** Fixed 20 Hz tick with the renderer interpolating; Q16.16 in `@lions/sim` with no floating point; seeded per-entity PRNG; data one way, commands → sim → state + events. **This package's diff under `packages/sim/` is empty** — `git diff --stat <base>..HEAD -- packages/sim` must print nothing at landing, and `pnpm test:determinism` is in Task 7's gate line because "cannot move" is a claim and the gate is the evidence. Every clock touched here is the FRAME clock; nothing presentation writes is ever read back by the sim.
- **The colour pipeline is not the default one and fails silently.** Every new colour is a `data/palette.json` key resolved at draw time through `ThreeRenderer.overlayColor(key, fallback)` — the pattern the muzzle-flash light already uses (`ThreeRenderer.ts:3059-3068`). No hex literal in renderer source; no raw hex in `data/vfx/*.json` (`palette_ref`, `vfx_emitter.schema.json:146-149`, no allowlist). A `ShaderMaterial` uniform takes `hexToLinear`, never `hexToUnit`: the composer's `OutputPass` encodes the frame to sRGB once at the end, so an un-linearised hex lands brighter than the palette entry authored (`vehicle-tracks.ts:507`).
- **Palette exemptions are named, not inferred.** The four are the textured buildings, the textured vehicles, terrain albedo/shade and the campaign board. **Nothing this package adds is exempt.**
- **Render-order bands come from `units/render-order.ts`**, the single source of truth — read it before setting one. The scorch decal is ground-tier world geometry (depth-tested, `depthWrite: false`), not an FX band.
- **`three` may only be imported under `packages/render/src/three/**`**, enforced by eslint; the rule's `paths` entry does not catch subpath imports (`three/addons/...`), so keep those inside by discipline. `packages/app` reaches a renderer only through `packages/render/src/api.ts` or the dynamic-import doors in `eslint.config.mjs`. **This package adds no door and changes no `api.ts` member.**
- **Pixi owes no parity.** Three-only effects are the intended end state since 2026-08-30. `packages/render/src/renderer.ts` stays byte-identical to `main`; none of the new managers is reachable from it.
- **The file boundary with Lane A** (`docs/superpowers/specs/2026-09-16-shell-upgrade-design.md:489-508`). This session owns `three/units/mesh-*.ts`, `three/ThreeRenderer.ts`, `packages/render/src/sheet.ts`, `tools/src/mesh_gait*`, `tools/units/rig.py`, the Meshy importers, `art/meshes/**`, `assets/meshes/**` and CLAUDE.md's "Mesh units" section. **Do not touch `packages/app/**`** (the shell programme's, `main.ts` and `theme.css` included) and **do not touch `three/units/overlays.ts` or `three/units/overlay-geometry.ts`** — Lane A's Tasks 15–16 hold those and are waiting on this landing.

## Rulings

The spec's Decisions, restated here as the ones that change what a task may do. Read the spec for each one's full reasoning.

- **R-A — "additive fireball" is the existing on-palette `hotCore`, never GPU additive blending.** Rejected on this backend and recorded in the schema (`vfx_emitter.schema.json:254-258`). Do not reintroduce `THREE.AdditiveBlending`.
- **R-B — The blast dispatches through the EXISTING direct vehicle-kill path** (`ThreeRenderer.ts:2749-2818`), reading the ADOPTED `catastrophic_kill.json`. No sim-side classification; `packages/sim` untouched.
- **R-C — No new wreck geometry.** The procedural wreck that shipped 2026-09-15 is the persistent wreck.
- **R-D — The frame clock stays for the impact fireball** (`shellHasLanded`). `hit_stop_ms` pauses interpolation in the render loop only; `screen_shake` is a render-time camera offset. Neither touches the 20 Hz tick or any sim state.
- **R-E — Before-captures first**, git-ignored under `.superpowers/art-captures/blast/<label>/`, attached to the PR. The after-set is the acceptance evidence; the lead judges on motion.
- **R-F — One `ThreeRenderer.ts` region**, in one task (Task 7), so Lane A's later merge is trivial.
- **R-G — One visual bless budgeted**, `combat` reports only, bless from CI numbers after the merge, never from the local darwin baseline.
- **R-H — What already ships is not re-implemented.** The spec's "What exists today" says so with file:line.
- **R-I — The 20 s column needs absolute rise/fade windows, not a bigger `durationMs`.** Every envelope is a fraction of `durationMs` (`smoke-plume.ts:857`), so 20 000 makes the rise 3.0 s and the fade 7.0 s. Task 3.
- **R-J — Hit-stop lives inside `ThreeRenderer.frame()`, not `main.ts`** — `packages/app` is Lane A's, and `frame()` already owns a frame-time clamp at exactly this boundary (`frameDtMs`, `:4400`).
- **R-K — Shake is applied in `threeCamera()` only** (`:4386`), on a COPY of the shared `Camera`, so `worldToScreen`/`screenToWorld` never shake and no DOM element jitters.
- **R-L — The golden gate cannot witness this package.** `vehicle` (tick 140, no kills, no indirect fire) contains no blast; `combat` has kills and is `gated: false` with `layerChecks: []`. **A red `vehicle` on this branch is a defect, not drift** — find it, do not bless it.
- **R-M — Two new `DEBUG_LAYERS` names (`scorch`, `blast-light`), exercised by the blast harness, not by a golden `layerChecks` entry** — a toggle on a scenario with no blast is a permanent zero delta, which is a failing check.
- **R-N — The scorch decal is a `vehicle-tracks.ts`-shaped one-off at 256**, flat palette-colour quad, no texture, not Phase 2's shared pool (GH-30).
- **R-O — Vehicle shroud bounds are measured from the LIVE nodes only**, excluding `death_root` — the mirror of the building rule at `ThreeRenderer.ts:3995-3999`.
- **R-P — `catastrophic_kill.json` is extended with `mesh_burst`/`mesh_plume` and nothing else.** Its `additive` hot core stays; its three presentation blocks are used as authored.
- **R-Q — `shell_impact.json` gains `mesh_plume` and the three presentation blocks; `structure_collapse.json` is not touched.**
- **R-R — Shake and hit-stop are capped per frame, rate-limited, and scale with the power term.** MAX, never sum; no re-entry while one runs.
- **R-S — The vehicle needs no new swap-hold**: `MESH_DEATH_SECONDS` (400 ms) already lands inside the shroud's dense window (192–840 ms), so `mesh-vehicle-death.ts` is not changed.

### Task 2: The emitter data, and what its three blocks mean once scaled

R-B adopts `data/vfx/catastrophic_kill.json` as the blast's authored emitter rather than authoring a second file beside it. // packages/render/src/three/blast-spec.test.ts
import { describe, expect, it } from 'vitest';
import type { EmitterSpec } from '../vfx/emitters';
import catastrophic from '../../../../data/vfx/catastrophic_kill.json';
import shellImpact from '../../../../data/vfx/shell_impact.json';
import { blastHitStopMs, blastLightSpec, blastShake } from './blast-spec';

const kill = catastrophic as unknown as EmitterSpec;
const impact = shellImpact as unknown as EmitterSpec;

describe('the adopted emitters carry what the renderer is about to read', () => {
  // R-P: `additive` is the on-palette hot core and stays; what was missing is
  // the flag that lets the POOLED fireball supersede the stacked quads, which
  // `structure_collapse.json` has had all along.
  it('catastrophic_kill hands its hot core to the pooled burst and its smoke to the pooled plume', () => {
    expect(kill.particles[0].additive).toBe(true);
    expect(kill.particles[0].mesh_burst).toBe(true);
    expect(kill.particles[1].mesh_plume).toBe(true);
  });

  // R-Q: measured -- shell_impact.json declares NO mesh_plume today, so a
  // mortar bomb gets a fireball and nothing that persists. The blast's third
  // element is simply absent on the mortar half.
  it('shell_impact gains a column and the three presentation blocks', () => {
    expect(impact.particles.some((p) => p.mesh_plume === true)).toBe(true);
    expect(impact.light?.color).toBe('vfx.fire');
    expect(impact.screen_shake?.amplitude_px).toBeGreaterThan(0);
    expect(impact.hit_stop_ms).toBeGreaterThan(0);
  });

  // The schema's own ceilings, asserted here so a later edit cannot quietly
  // author past them and rely on validate:data being run.
  it('stays inside the schema ceilings it is validated against', () => {
    expect(kill.screen_shake!.amplitude_px!).toBeLessThanOrEqual(24);
    expect(kill.hit_stop_ms!).toBeLessThanOrEqual(120);
    expect(impact.screen_shake!.amplitude_px!).toBeLessThanOrEqual(24);
    expect(impact.hit_stop_ms!).toBeLessThanOrEqual(120);
  });
});

describe('scaling by the caller\'s power term', () => {
  it('a full-power blast is the emitter verbatim', () => {
    const light = blastLightSpec(kill, 1);
    expect(light).toEqual({ color: 'vfx.fire', intensity: 3.5, radius_tiles: 7, decay_ms: 500 });
    expect(blastShake(kill, 1)).toEqual({ amplitudePx: 9, durationMs: 420, falloffTiles: 14 });
    expect(blastHitStopMs(kill, 1)).toBe(70);
  });

  // G0 #14: "mortar shares at its own power". SHELL_PROFILES.mortar is 0.3.
  it('a mortar bomb gets three tenths of it', () => {
    expect(blastLightSpec(kill, 0.3)!.intensity).toBeCloseTo(1.05, 6);
    expect(blastShake(kill, 0.3)!.amplitudePx).toBeCloseTo(2.7, 6);
    expect(blastHitStopMs(kill, 0.3)).toBe(21);
  });

  // DURATION and REACH are not scaled -- only STRENGTH is. A weaker blast is
  // quieter, not shorter and not smaller in the world: a shake whose duration
  // shrank with power would read as a different EFFECT rather than a smaller
  // one, and a light whose radius shrank would stop touching the ground it
  // is lighting.
  it('scales strength and leaves duration and reach alone', () => {
    expect(blastShake(kill, 0.3)!.durationMs).toBe(420);
    expect(blastShake(kill, 0.3)!.falloffTiles).toBe(14);
    expect(blastLightSpec(kill, 0.3)!.decay_ms).toBe(500);
    expect(blastLightSpec(kill, 0.3)!.radius_tiles).toBe(7);
  });

  it('answers null and zero for a missing emitter or a zero power, never a half-built spec', () => {
    expect(blastLightSpec(null, 1)).toBeNull();
    expect(blastShake(null, 1)).toBeNull();
    expect(blastHitStopMs(null, 1)).toBe(0);
    expect(blastLightSpec(kill, 0)).toBeNull();
    expect(blastShake(kill, 0)).toBeNull();
    expect(blastHitStopMs(kill, 0)).toBe(0);
  });

  it('an emitter that declares no presentation blocks is silent, not a default', () => {
    const bare = { id: 'x', trigger: 'weapon_fire', layer: 'above_units', particles: [] } as unknown as EmitterSpec;
    expect(blastLightSpec(bare, 1)).toBeNull();
    expect(blastShake(bare, 1)).toBeNull();
    expect(blastHitStopMs(bare, 1)).toBe(0);
  });
});

### Task 3: The twenty-second column

The page asks for a 20 s smoke column and `SmokePlumeManager.spawn` already takes `durationMs`, so the temptation is a one-argument change. R-I is why that is wrong, and it was read rather than guessed: `step` computes `progress = ageMs / durationMs` (`smoke-plume.ts:857-868`) and **every** envelope is a fraction of it — `smokePlumeRiseEnvelope` (`:399`), `smokePlumeOpacity` (`:422`), `smokePlumeSpread` (`:440`).
