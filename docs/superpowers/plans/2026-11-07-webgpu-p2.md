# WebGPU-primary P2: roads, selection rings, wind and the banding (plan, GH-943)

Written 7 Nov 2026 after the lead's ruling of the same day on the P1 sheet v2 (PR 1082): **P1 passes for G** (the node renderer on
WebGPU), and before any talk of making WebGPU the default, P2 ports what the node path still lacks:

1. roads (the ground shader's procedural road block);
2. selection rings;
3. wind (foliage sway on the sim clock);
4. the banding in the shadow penumbra and the lit ground on the node frames, diagnosed first.

Non-WebGPU browsers keep the legacy renderer (L). F (node on WebGL2) stays a test arm: its CI captures stay, because they are the
deterministic parity arm, but there is no F performance work and no F timing in P2.

P2 branches from origin/main (4cdac8fdc or later) and keeps legacy the default. No node key is blessed before P7. Each task is one PR
with one reviewer. The P1 plan this follows is `_coord/webgpu-primary/p1-plan.md` (it never lived under `docs/superpowers/plans/`).

Estimate: 9 tasks, 9–13.5 agent-days. T8's size is set by T2's finding.

## Facts (read in the code on origin/main; they override the design)

**The node ground is missing more than roads.** `GroundMaterial` (terrain/mesh.ts) is a `MeshStandardMaterial` whose whole look is
one `onBeforeCompile` splice. The node backend ignores the splice, so G draws the bare vertex-colour palette: no five-slot albedo, no
macro field, no road, no relief read (slope light, height contours), no wet terms. The P1 sheet shows it: the G z2.5 crop is flat green
with no grass texture, where L is textured.
- **The road block cannot be ported on its own.** It mixes the road, shoulder and rut tones into `diffuseColor` BEFORE the albedo ratio
  multiply, and scales the five surface weights by `(1 - surface)`. A road port is therefore the dry blend's port: the albedo slots, the
  height bias, the road and the macro, in one graph (T3).
- Relief read is in the same splice (T4). The wet terms (`THEME_WET`) are not in P2; a wet map on node draws dry and SAYS so (T1's
  partial census).
- Texture slots change after the graph is built (`uniforms[u.map].value = tex` when an image lands, `ThreeRenderer.ts:1685`), so a twin
  re-syncs texture nodes the way `fog-pass.node.ts` re-reads numbers (`onRenderUpdate`).

**Selection rings are hidden on node.** `SelectionRingBatch` (units/selection-ring.ts) builds a `ShaderMaterial`, and
`censusUnported` hides every `ShaderMaterial` object. Three batches use it: the selection ring, `TEAM_RING` (every own unit not
selected, so it is in the `vehicle` scenario) and `WOUND_RING` (the arc mode, pulsing on the SIM clock, `uTimeSec`). `endFrame` and
`setClock` write `this.mesh.material.uniforms`, so swapping `mesh.material` to a node twin needs the uniform record held apart first.

**Wind and the vehicle bend are one hook.** `swayingFoliageMaterial` (terrain/decor-mesh.ts) splices the wind (GH-984 N1) AND the
disturbers (N2 vehicles, N3 rotor wash) into one program per variant (foliage/trunk, dry/wet).
- three 0.186.1 `NodeMaterial.setupPosition` applies `batch(object)` to `positionLocal` BEFORE `positionNode`, so a `positionNode` sees
  the batched position. The instance ORIGIN (the batching matrix's translation, which the lean and the gust phase read) is not exposed:
  BatchNode keeps the matrix as a local.
- The node shadow pass draws with the material's `positionNode` unless `castShadowPositionNode` is set (`Renderer.js:3574`). Legacy
  shadows and AO keep the REST pose (R-11, `terrain-rendering.md`). The node AO pre-pass uses an `overrideMaterial`
  (`post-chain.node.ts:315`), so it keeps the rest pose by construction.
- `wind.test.ts` transpiles the GLSL `rlWindLean`/`rlWindGust` and RUNS them against `windLean`/`windGust`. The gust hash is integer
  maths (`tileHash`, multipliers from `tile-hash.ts`).

**The census would blind the parity arm after a port.** `matchNodeStatements` (capture-protocol.ts) runs the node backend's own
`censusUnported` on the LEGACY scene, so L-matched hides what the node chain cannot draw. After the ring port, the node scene holds the
twin, but the legacy scene still holds the `ShaderMaterial`, and the census would still hide it: the ring's legacy delta would read 0
and its parity ratio would be meaningless. The census needs a list of ported material keys (T1).

**The T7 parity gap in the 7 Nov follow-ups is already closed.** PR 1085 removed the line that turned the legacy AO off in
`matchNodeStatements`; `node-toggle.test.ts` pins the reverse. No P2 task.

**What is known about the banding (no conclusion yet):**
- r186's node `PCFShadowFilter` is the same 5-tap Vogel disk, rotated per pixel by interleaved-gradient noise, as legacy PCF since r182
  (`ShadowFilterNode.js:48-80`). Bias -0.0005, normal bias 0.02 and the 4096 map are shared (`lighting.ts`).
- The node scene pass is HalfFloat colour with a depth24plus-stencil8 depth, and the SMAA input is a HalfFloat RTT (P1 T2).
- The dither is one LSB of IGN after the grade, on BOTH paths, and only while `uGradeOn > 0.5` (`output-grade.ts:50`, T3's twin).
- L's ground is textured and G's is not, so G shows any quantisation that L's texture masks. The sheet also reads G's centre luma
  higher than L's (93.1 vs 86.3 at z1, PR 1085).
- `GTAONode` at half resolution with `DenoiseNode` is not `GTAOPass`; AO multiplies the lit ground.

**Rules carried from P1:**
- **The same-PR rule:** a legacy GLSL file and its `.node.ts` twin change in the same PR (`tools/src/ci/twin-check.ts`).
- **Shared maths by injection:** maths is written ONCE against `Ops<T>` (`fog-ops.ts`), tested on numbers through `NUMBER_OPS`,
  and handed to the node backend as values from an app-side module (`output-maths.ts`'s pattern). A twin imports legacy files as TYPES
  only, or the node chunk statically loads the ThreeRenderer chunk and the bundle census fails.
- **Uniform records stay records:** a twin reads the legacy object's `uniforms.X.value` table (vectors by reference, numbers and textures
  re-read every render), so no `ThreeRenderer` call site changes.
- Twins import only addon-free modules. `three` stays under `packages/render/src/three/**`.
- Sim clock only: every animated term reads `presentationSimMs`, a zero-time repaint moves nothing.
- `render-order.ts` stays the one source of every `renderOrder`; the colour pipeline is unchanged (linear vertex and uniform colours,
  ground albedo `NoColorSpace`, no envMap on ground, decals or rings).

**Rulings that bound P2 (7 Nov):** the parity bands stay REPORT-ONLY until two weeks of CI readings; `visual-backends` votes on frame
content only (GPU validation errors, black or flat frames). The P1 sheet tool (`webgpu-p1-sheet.ts`) is in PR 1082, still open.

### T2. Banding diagnosis (1–1.5 d, Opus, CI + one Metal lock hold)

Diagnose before fixing. The output is a finding, not a fix.

**Changes:**
- New tools/src/golden-diff/banding.ts (pure) and its test: `bandingIndex(rgba, w, h, crop)`.
  - Over the crop, it masks the pixels on a SHALLOW gradient: a 9x9 box-blurred luma that changes by 0.5 to 4 levels over 32 px.
  - Along rows and columns, it measures runs of identical 8-bit luma inside the mask. The index is the fraction of masked pixels in runs
    of 12 px or more that end in a step of exactly 1 level.
  - An empty mask is a REFUSAL (exit 2), never a pass: the casebook's empty-array shape.
- New tools/src/perf/webgpu-banding-probe.ts. On one page per arm (L-matched, G, and F on CI only), it photographs two fixed crops of
  the sheet framing (`wadi_halam_4`, booted camera, z1): a penumbra crop on the edge of a large soft shadow, and an open lit-ground crop.
  For each hypothesis below it reads `bandingIndex`, toggled on BOTH arms:
  - H0, exposure: `ground-albedo` and `macro` hidden on L, so both arms show the flat palette ground. If L-flat bands like G, the banding
    is quantisation the texture masked, and T3 changes the picture.
  - H1, dither: read `uGradeOn` and `uGradeDither` on both arms; force the dither on and off on each; check the node dither's y flip.
  - H2, precision: read every target's type on the node chain (scene pass, SMAA RTT, output), the canvas format
    (`bgra8unorm` or `rgba16float`) and the context's colour space. Swap the scene pass to FloatType on node.
  - H3, shadow filtering: `shadow.radius` 0, 1 and 4; BasicShadowMap on both arms; VSM on node; read the node shadow depth format.
  - H4, AO: `ao` hidden on both arms.
  - H5, sky light: `environment` hidden on both arms.
- docs/agent-notes/webgpu-backend.md: a "Banding (P2 T2)" section with the table, the cause and the recommended fix for T8.

**Gates:**
- `bandingIndex` is two-sided on synthetic ramps: a 16-level ramp over 512 px quantised to bytes reads ≥ 0.8; the same ramp with ±0.5 LSB
  IGN dither reads ≤ 0.1; a flat frame refuses. Falsify each: drop the 1-level step test (dithered reads high), and drop the empty-mask
  refusal (flat passes).
- The metric SEES the reported defect: on the P1 v2 frames (`_coord/webgpu-primary/p1-sheet-v2/`), G's penumbra and lit-ground crops
  read above L-shipped's. If they do not, the crops or the metric are wrong. Stop and report; do not tune the thresholds to the answer.
- Each hypothesis toggle is watched MOVING the frame (a toggle that changed nothing tested nothing): the probe refuses a hypothesis
  whose A/B delta is 0 on both arms.

**Runs:** CI `workflow_dispatch` on SwiftShader (L, wgl2, wgpu), then ONE Metal lock hold, own port, music off, load ≤ 4 stated.

## Parity method

- **The ratio** is P1's: r = Δnode / Δlegacy-matched, where Δ is the shown-minus-hidden meanAbsChannelDelta (primary) and the changed
  pixels (secondary). Report-only (ruling 3).
- **The node A/B must change the frame.** Every ported layer has a parity row, and parity-run prints `DEAD` when the node delta is under
  its node floor (a third of the smallest of 3 CI runs per key, each watched going red). A dropped port reads DEAD whatever the band says.
  Each task's falsification breaks its own layer on the node arm and watches it read DEAD.

## Risks

1. **The instance origin under BatchedMesh.** r186 does not expose the batching matrix to a `positionNode`. Reading it through BatchNode's
   own fetch depends on a private layout; the pin fails loudly at a three upgrade. The fallback is a per-instance origin attribute, which
   costs memory: report before taking it.
2. **WGSL uniformity.** An implicit-gradient sample inside non-uniform control flow does not compile on WebGPU. It is caught by the content
   gate (a GPU validation error), but only on the wgpu arm. Write the road block branch-free first.
3. **Ground cost on G.** Five taps, two controls, the macro and a road on every ground fragment. P1 measured G at x0.874/x0.956 with a bare
   ground. The sheet re-checks the 1.05 bar; a miss is reported with the branch-free road as the first suspect.
4. **The banding may be shared.** If H0 shows L-flat bands too, the defect is the missing texture plus a dither that only runs with the
   grade, on both paths. A legacy change then needs a CI bless and the lead's look.
5. **Texture re-sync.** A slot image lands after the graph is built. A texture node bound by value draws the white pixel forever, and the
   strength-0 fail-soft hides it (the ground looks plausible). T3's record gate covers it.
6. **Census blindness.** A ported `ShaderMaterial` hidden on L-matched makes its parity ratio infinite or undefined, not red. T1's
   exemption, and T5's L-matched gate.
7. **Same-PR friction.** wind.ts and relief-read.ts gain twins, so unrelated changes there (rain slant, relief constants) must touch the
   twin. That is the rule doing its job; reviewers should not waive it.
8. **Shadow pose.** A node foliage material with a `positionNode` and no `castShadowPositionNode` sways its shadow: a visible difference
   that no layer check isolates. T6 pins it.
