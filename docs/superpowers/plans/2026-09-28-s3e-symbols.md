# S3e Symbols: the G1-approved sheet in the app. Implementation plan (replaces Tasks 11–12 of the Phase 3 app plan)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the symbol family the lead approved at G1 as one drawn source, with no Unicode dingbats left at the sites it covers:
- The seven role marks become the APP-6 set from round 2.
- Every order gets the round-4/5 chevron-stadia aim with its APP-6 tactical graphic animated around it, coloured by order family from `data/palette.json`.
- The same marks draw the dock, the order row, the strip, the chips and cards, and the cursor.
- A named-list check in `pnpm validate:ui` stops the retired dingbats from coming back.

**Architecture:**
- Two new pure modules hold the geometry. Each has a colocated test and no DOM, no `t()` and no CSS, so both `packages/app` and the Node-side cursor plugin can import them.
  - `packages/app/src/ui/symbol.ts`: the static sheet (roles, static order marks, utility marks) and `symbolSvg`.
  - `packages/app/src/ui/order-sight.ts`: the aim, each order's animated surround as a function of phase, the family-to-palette-key table, and the frame phases.
- HUD consumers draw through `symbolSvg` in `currentColor`. Family colour reaches the HUD only through semantic tokens in `theme.css`.
- The cursor plugin (`packages/app/vite-plugin-cursors.ts`, outside the scan root) resolves the same palette keys to hex at build time. It bakes the dark halo into each data URI and emits one rule per frame. It also emits `:root[data-cvd=…]` override rules, so `team.*` colours follow the colour-vision setting live.
- A small injected-dependency frame driver, `packages/app/src/input/cursor-anim.ts`, replaces `main.ts`'s inline `ensureCursorAnim`. It pauses while the tab is hidden and holds the static frame 0 under reduced motion.

**Tech Stack:** TypeScript strict, vitest (node for pure modules, jsdom for DOM files), Vite plugins, Playwright (tools only). No new dependencies. Nothing under `packages/render/**` or `packages/sim/**`.

**Interface:**

```ts
export interface CursorAnimDeps {
  writeFrame(frame: number): void;                 // canvas.dataset.cursorFrame = String(frame)
  setInterval(fn: () => void, ms: number): unknown;
  clearInterval(handle: unknown): void;
  reducedMotion(): boolean;                         // ui/motion.ts prefersReducedMotion()
  hidden(): boolean;                                // document.visibilityState === 'hidden'
}
export interface CursorAnimDriver {
  /** Called every hover tick (~60 Hz). Idempotent; restarts on a name change, or after a pause when conditions allow. */
  show(name: CursorName): void;
  /** visibilitychange and settings changes: stop now (writing frame 0) or allow the next show() to resume. */
  refresh(): void;
  dispose(): void;
}
export function cursorAnimDriver(table: typeof ANIMATED_CURSORS, deps: CursorAnimDeps): CursorAnimDriver;
```

**Behaviour:**
- A name that is not animated stops the timer.
- A new animated name writes `0` and starts `setInterval(intervalMs)`.
- While `reducedMotion()` or `hidden()` holds, the driver writes `0` and starts no timer. Frame 0 is the rest pose (Q14), so this is the static first frame.
- Each tick re-checks both conditions. `reducedMotion()` is read at most once per `show` name change and once per tick, never at 60 Hz. It is cached per paused name until `refresh()`.
- `main.ts` adds a `document` `visibilitychange` listener that calls `driver.refresh()`, removed through `onDispose`.
- The settings bus already notifies on change (`main.ts:778-790`, `settingsBus`). Subscribe `driver.refresh()` if that subscription is reachable from `bootBattlefield`'s scope; otherwise the next name change picks the new setting up. Record which one applies in the commit.

- [ ] **Step 1: Write the failing tests.** Each case must hold:
  - `show('attack')` writes 0, then 1, 2 … at `intervalMs` and wraps.
  - `show('attack')` repeated does not restart the cycle.
  - `show('blocked')` stops the timer.
  - A name change resets to 0.
  - With reduced motion on, `show('move')` writes 0 and never starts an interval.
  - Hiding and then calling `refresh()` stops the timer and writes 0. Showing again resumes from 0 on the next `show`.
