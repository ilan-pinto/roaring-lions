# Accounts A0 and A1: shared coin rules, then Steam sign-in, export and delete (plan, GH-1075)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the pure Roar-coin rules into a new leaf package, `@lions/economy` (A0). Then give the Worker an identity
core with Steam as the first provider: sessions, CSRF, export, delete with a KV tombstone, and the closed switch (A1, L1 = S).
A profile screen and a menu chip sit behind `?accounts`. Nothing syncs progress yet.

**Architecture:** A0 is a refactor with no behaviour change. The app keeps thin re-export modules, so no caller changes.
A1 adds `packages/worker/src/account/` and a second D1 database (`ACCOUNTS`, its own `migrations-accounts/`), plus one KV
namespace (`ACCOUNT_TOMBSTONES`). Every binding is optional in `Env`, and an unbound one answers 503, so the code can merge
before the lead creates the resources. Only the last task, which is lead-gated, writes the bindings into `wrangler.jsonc`.

**Tech Stack:** TypeScript strict, Cloudflare Workers, D1 (`node:sqlite` in tests through `test-d1.ts`), Workers KV,
vitest, jsdom, eslint flat config.

**Spec:** `docs/superpowers/specs/2026-11-07-accounts-profiles-design.md` (PR 1101, rev `fbea293b4`). Lead rulings on
GH-1075 (7 Nov): every decision but L1 as the spec recommends, and then L1 = **S, Steam + guest first**, passkey linked later.
That ruling also releases A1 from the L2 hostname hold. Read the spec's §1.3, §1.5, §1.7 to §1.9, §2.1, §2.2, §2.5, §2.6,
§6 and §7 (A0, A1) before any task.

**Estimate:** A0 about 1.5 agent-days (6 tasks). A1 about 5 agent-days (10 tasks, one of them the lead's).

## §0. The spec checked against the code (origin/main `336c5bc42`)

These facts come from reading the code. Where one disagrees with the spec, this plan follows the fact and says so here.
Items marked **ruled** are this plan's decisions under the no-questions rule. Items marked **lead** are batched in the report.

**A0, the coin rules**

1. **Four modules cannot move "byte for byte" (§2.6), because each mixes rules with storage or i18n.**
   - `roar-wallet.ts`: `ROAR_KEY`, `loadRoar`, `saveRoar` and `snapshotRoarText` are storage. Its test scans the app for the
     key literal (`roar-wallet.test.ts`, "THE ONE READER AND WRITER").
   - `roar-earn.ts`: `settleVictory` and `settleRoarAtBoot` take a `LedgerStore`.
   - `brigade-account.ts`: `ACCOUNT_KEY`, `loadAccount`, `saveAccount` and `resetAccount` are storage. `redeemCoupon`, which
     §2.6 lists, lives here.
   - `campaign-close.ts`: `campaignComplete` calls `regionProgress`, which calls `gateSentence`, which calls `t()`.
     `closingExchange` and `boardRestingLine` use `t()` themselves.

   **Ruled:** the pure half of each moves. The storage and i18n half stays in the app, and the app module re-exports the
   moved names, so no caller changes. `campaignComplete` is re-expressed in the economy package over `gateRequirement`
   (moved out of `gate-sentence.ts`, which has no `t()` in it) instead of `regionProgress`. The two are equivalent:
   `gateSentence` returns null exactly when `gateRequirement` does. An equivalence test pins it (Task 0.4).
2. **`@lions/economy` imports VALUES from `@lions/sim`, not "only types".** `stores-model.ts` and `gateRequirement` call
   `conductAtLeast`, `starsEarned` and `isBoughtOnly`. **Ruled:** economy may import `@lions/sim` and `@lions/data`, and
   nothing else. The Worker already bundles `@lions/sim` through `@lions/net`, so this adds nothing to its bundle.
3. **`stores-model.ts` moves whole.** `storeItems` reaches `meanPay`, which reads `CAMPAIGN_CREDITS`. The file is pure:
   `@lions/sim`, `@lions/data` and the wallet only. `tools/src/campaign_credits.test.ts` pins `CAMPAIGN_CREDITS` by reading
   `packages/app/src/ui/stores-model.ts` as TEXT, so its path changes with the move.
4. **The tests stay in the app. This departs from "their tests move with them".** Most of them build a
   `memoryLedgerStore` from `ledger-store.ts`, which the economy package must not import. Run through the re-exports,
   they prove both the moved rules and the re-export surface every caller uses. New economy tests live in
   `packages/economy/src/`.
5. **The G-V2 fence would leak.** `ROAR_FENCE` (`tools/webgpu_fences.mjs`) matches the paths `**/roar-wallet`,
   `**/roar-earn` and `**/account-view`. After A0, `packages/app/src/net/*` could import `@lions/economy` directly and
   reach `singlePlayerView`. The versus room in `packages/worker/src/match/` has no fence at all, and the Worker gains the
   dependency in A0. **Ruled:** `ROAR_FENCE.group` gains `@lions/economy` and `@lions/economy/*`, and a new block fences
   `packages/worker/src/match/**`. `tools/src/roar_fence.test.ts` gains both cases and a control:
   `packages/worker/src/account/` may import it.
6. **`sha256.ts` moves too.** `redeemCoupon` takes a synchronous `hash`, and A2's server coupon route needs the same one.
   The file is pure, 54 lines.
7. **For A2, not built here.** The server's `spend`, `campaign` and `slots` routes will need code that is not on §2.6's
   list:
   - `garageUnits` and `coinHalf`, which build a `StoreInput` inside `main.ts`;
   - `sanitiseLedger` (`ledger-shape.ts`);
   - `importSlot` (`profile.ts`).

   The A2 plan moves them. A0 does not.

## Global Constraints

- The sim is untouched. `pnpm test:determinism` passes before and after every task, and nothing under `packages/sim/` changes.
- **Dependency direction:**
  - `@lions/economy` imports `@lions/sim` and `@lions/data` only;
  - `app` and `worker` import it;
  - `sim`, `net`, `render`, `app/src/net/**` and `worker/src/match/**` never do (G-V2).
- No `any`, no non-null assertions. `pnpm typecheck` runs in CI (memory: "CI runs typecheck"). Run it with lint.
- **Cookies, verbatim from the spec:**
  - `__Host-rl_session=<32 random bytes, b64url>; Secure; HttpOnly; SameSite=Strict; Path=/; Max-Age=2592000`;
  - `__Host-rl_pre=<32 random bytes>; Secure; HttpOnly; SameSite=Lax; Path=/; Max-Age=300`.
- **Sessions:** 30 days from last use, 180 days at most, slid at most once a UTC day, re-sending `Set-Cookie` on a slide. At
  most 10 per member, the oldest evicted. `fresh_until` is 5 minutes after a sign-in.
- **Challenges:** 32 random bytes, stored as `sha256`, 5-minute expiry, consumed once.
- **Rate limits:**
  - `ACCOUNT_LIMIT` (`1007`): 10 a minute per IP;
  - `ACCOUNT_OP_LIMIT` (`1008`): 60 a minute per IP;
  - `acct-new-ip`: 5 a day; `acct-new-all`: 500 a day;
  - `acct-ops`: 400 a day per member; `acct-all`: 20,000 a day.
- **No IP and no user agent is ever stored,** only `ipKey`. No email is stored, and no persona name, avatar, friends list or
  session ticket. `GetPlayerSummaries` is never called.
- **No CORS:** no `access-control-allow-*` on any `/api/account/*` response, and `OPTIONS` answers 405.
- **A missing `flags.accounts` row means CLOSED.** Sign-in for an existing identity, `export`, `delete` and `gone` work
  while it is closed.
- **Tombstones:** KV key `tomb:` + `member.id_hash`, value `{deletedAt}`, `expirationTtl` 7,776,000 s (90 days).
  `id_hash` is the lowercase hex SHA-256 of the `public_id`'s UTF-8.
- **Telemetry stays unlinked:** no telemetry event, feedback context or `/stats` query carries a member id, public id,
  display name, SteamID or session.
- The app makes **no** `/api/account` request unless `?accounts` is on the URL (A1). `?fresh` never reads or writes the
  server.
- Every chrome string goes through `t()` and `en.json`, and `pnpm validate:ui` passes. Issue refs are written GH-NNN.
- House rules: no `git add -A` (use `git commit -- <paths>`), no `git checkout <file>`, no `git stash`. No local
  `ui:routes`, `ui:shots` or `golden-baseline`. No deploys, secrets or production D1.

## Review Focus

1. **Cancel at Steam.** A player who presses Cancel on Steam's page comes back with `openid.mode=cancel`. They should land
   on the profile with "Sign-in was cancelled", not an error, and the challenge should be gone. (Task 1.5,
   `cancel_returns_cancelled`.)
2. **Reload or Back on the return URL.** The challenge is already consumed. The player should see "That sign-in link has
   expired. Try again" (`r=expired`), with no 500 and no second session. (Task 1.5, `replayed_return_is_expired`.)
3. **Two sign-ins racing for one new SteamID** (a double click, two tabs). Two challenges both pass, and both create calls
   run. There should be exactly one member, both tabs signed in to it, and no 500 from the `UNIQUE (provider, subject)`
   conflict. (Task 1.5, `concurrent_first_signins_make_one_member`.)
4. **Display names in Hebrew, with emoji, or with zero-width characters.** Length is counted in code points after
   `cleanCallsign`, never in UTF-16 units. 20 emoji are accepted, 21 are refused, and a name that is all format characters
   is refused. (Task 1.6, `display_name_counts_code_points`.)
5. **A session at its 180-day wall.** A slide never moves `expires_at` past `absolute_at`. `Max-Age` is never negative. At
   `absolute_at` itself the session is gone (401). (Task 1.3, `slide_stops_at_absolute`.)
